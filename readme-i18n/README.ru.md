# Graw

Веб-панель управления сервером с интерфейсом в стиле настольной операционной системы (окна, панель задач, ярлыки на рабочем столе) и встроенным стандартным режимом панели в стиле 1Panel. Фронтенд построен на Vue 3 + Vite, бэкенд — на FastAPI.

Помимо локальной машины, Graw позволяет включать другие хосты в единую панель как «дочерние узлы» через **туннель Agent + парные ключи доступа**: переключаться между хостами в одном месте и управлять контейнерами, сайтами, файлами, терминалом и брандмауэром нескольких серверов.

## Как скачать?

Graw работает в контейнере, но **все его операции управления (контейнеры/образы Docker, установка из магазина приложений, веб-терминал, процессы/брандмауэр, настройка сайтов и т. д.) должны выполняться на самом хосте**. Поэтому **нельзя** просто запускать контейнер с `-p порт:8000` — его нужно запускать в описанном ниже «полном режиме хоста»: контейнер должен иметь доступ к Docker хоста (сокет) и к корню хоста (`/host`), а также обладать правами уровня хоста (`privileged` + `pid host`).

**Способ 1: Linux-сервер (рекомендуется; сеть host, панель слушает порт 8000 хоста напрямую)**

```bash
docker run -d --name graw-panel \
  --network host --pid host --privileged \
  -v /opt/graw/data:/app/backend/data \
  -v /:/host:rslave \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -e HOST_ROOT=/host \
  -e GRAW_HOST_DATA=/opt/graw/data \
  -e TZ=Asia/Shanghai \
  shunx/graw:latest
```

После запуска откройте `http://<IP-сервера>:8000`.

**Способ 2: сеть bridge (свой порт доступа, например 8041)**

```bash
docker run -d --name graw-panel \
  -p 8041:8000 --pid host --privileged \
  -v /opt/graw/data:/app/backend/data \
  -v /:/host:rslave \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -e HOST_ROOT=/host \
  -e GRAW_HOST_DATA=/opt/graw/data \
  -e TZ=Asia/Shanghai \
  shunx/graw:latest
```

После запуска откройте `http://<IP-сервера>:8041`.

**Способ 3: Docker Compose (в репозитории уже есть конфигурация с повышенными правами)**

```bash
git clone https://github.com/wuhulab/Graw.git
cd Graw
docker compose up -d --build
```

Значение параметров (без них панель не сможет полноценно управлять хостом):

- `--privileged`: даёт контейнеру все возможности ядра; иначе `chroot /host`, iptables/брандмауэр, монтирование и т. п. не будут работать внутри контейнера.
- `--pid host`: общее с хостом пространство имён процессов; только так управление процессами и системный мониторинг видят все процессы хоста.
- `--network host`: сеть хоста, панель слушает порт 8000 хоста напрямую (в способе 2 вместо этого используется `-p перенаправление портов`).
- `-v /:/host:rslave` + `HOST_ROOT=/host`: корень хоста монтируется внутрь контейнера в `/host`, и панель через `chroot /host` работает с файлами и командами хоста (nginx/certbot/crontab и т. д.).
- `-v /var/run/docker.sock:/var/run/docker.sock`: подключение к Docker-движку хоста (управление контейнерами/образами/логами).
- `/opt/graw/data` — каталог данных панели (монтируется с хоста); `GRAW_HOST_DATA=/opt/graw/data` сообщает, где на хосте лежит файл docker-compose, — это нужно, чтобы магазин приложений Docker мог завершить установку.

> ⚠️ **Предупреждение о безопасности**: фактически такой контейнер получает права уровня root на хосте, поэтому разворачивать его рекомендуется только в доверенной среде. **Сразу смените пароль по умолчанию** после первого входа и бережно храните файлы учётных данных в `backend/data/`.

## Возможности

- **Система учётных записей и прав** — вход по JWT, роли (администратор / обычный пользователь), управление аккаунтами, принудительная смена пароля, журнал входов, управление онлайн-сессиями (онлайн определяется по сроку действия токена и времени последней активности)
- **Два режима интерфейса** — режим рабочего стола (окна / панель задач / ярлыки, с перетаскиванием, разворачиванием и сворачиванием) и стандартный режим панели в стиле 1Panel (боковое меню с группами + вкладки)
- **Управление несколькими узлами** — главная панель подключает дочерние узлы через туннель Agent + парные ключи доступа, поддерживает развёртывание SSH-ключей, переключение хоста на уровне запроса и ограничение возможностей удалённых дочерних узлов
- **Мониторинг системы в реальном времени** — CPU, память, диск, сеть, нагрузка; данные и графики передаются по WebSocket, доступен запрос истории метрик
- **Управление сайтами** — CRUD виртуальных хостов Nginx / OpenResty / Apache, запуск и остановка, генерация и просмотр конфигурации; сосуществование с 1Panel/OpenResty и автоматическое обнаружение внешних сайтов
- **WAF и расширение сайтов** — веб-application firewall, псевдостатика/rewrite, кеш и расширенные настройки сайта, статистика сайта
- **Управление базами данных** — MySQL / MariaDB / Redis / PostgreSQL / MongoDB: подключения, просмотр баз и таблиц, выполнение SQL / команд Redis, анализ медленных запросов
- **Управление Docker** — просмотр контейнеров и образов, запуск, остановка, логи, статистика ресурсов; совместимость с форматами вывода docker и podman
- **Магазин приложений** — установка приложений в один клик по рецептам YAML (установка = `docker compose`), редактирование собственного compose и журнал установки
- **Управление файлами** — просмотр каталогов, загрузка и скачивание, изменение прав, архивация и распаковка, копирование и переименование; буфер обмена в стиле Windows (Ctrl+C/V/Delete) и загрузка папок перетаскиванием
- **Корзина** — удалённые по ошибке файлы попадают в корзину, есть восстановление и автоматическая очистка по дням (на всех узлах)
- **Веб-терминал** — терминал в браузере на базе xterm.js для прямого управления сервером (WebSocket аутентифицируется через `?token=`)
- **Планировщик / Брандмауэр / SSL** — управление Cron-выражениями (crontab / schtasks), порты и чёрные/белые списки IP (iptables / netsh, включая контроль входящего и исходящего трафика опубликованных портов Docker), загрузка сертификатов и запрос Let's Encrypt
- **Безопасность и эксплуатация** — защитный вход ShunX, защита веб-страниц от изменений (оповещения по WS в реальном времени), единые правила брандмауэра, проверка состояния, резервная копия панели, мониторинг сервисов, проверка сроков действия сертификатов, центр уведомлений
- **Прочее** — центр логов, управление процессами, заметки, проброс внутренней сети (Frp), сетевое хранилище, пользователи FTP, управление версиями PHP, набор инструментов, открытый протокол плагинов (GPOP)

## Быстрый старт

### Требования

- Python 3.8+ (в продакшн-образе — 3.11)
- Node.js 16+
- (опционально) Docker-движок для функции управления Docker

### Запуск в один клик (разработка)

```bash
# Linux / macOS
./start.sh

# Windows
start.bat
```

Скрипт при необходимости создаёт виртуальное окружение, устанавливает зависимости и запускает бэкенд и фронтенд одновременно.

### Ручной запуск

**1. Запуск бэкенда**

```bash
cd backend
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt  # при первом запуске
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
# или через скрипт разработки
python start.py
```

**2. Запуск фронтенда**

```bash
cd frontend
npm install
npm run dev                      # → http://localhost:5173, Vite проксирует /api и ws на :8000
```

> В PowerShell/cmd в Windows `&&` не поддерживается — разделяйте команды точкой с запятой `;`.

### Продакшн-сборка

Сборка фронтенда для продакшна попадает в `frontend/dist`; бэкенд автоматически обнаруживает и подключает этот каталог как статику:

```bash
cd frontend
npm run build
```

Затем просто запустите бэкенд — полное приложение будет доступно по `http://localhost:8000` (фронтенд отдаётся бэкендом с того же источника, настройка CORS не нужна). Можно также собрать образ и развернуть его через `Dockerfile` / `docker-compose.yml` из репозитория.

## Обзор API

Все эндпоинты имеют префикс `/api/*`; кроме `/api/auth/login` и `/api/health`, всем требуется заголовок `Authorization: Bearer <token>`.

| Модуль | Префикс | Описание |
|------|------|------|
| Auth | `/api/auth` | Вход, текущий пользователь, смена пароля, управление пользователями (администратор) |
| Agent | `/api/agent` | Аутентификация между дочерними узлами (обмен парных ключей на JWT) |
| System | `/api/system` | CPU, память, диск, сеть, нагрузка, поток WebSocket в реальном времени |
| Nodes | `/api/nodes` | Управление несколькими узлами и переключение текущего управляемого хоста |
| Sites | `/api/sites` | Управление виртуальными хостами (Nginx / OpenResty / Apache) |
| WAF | `/api/waf` | Правила веб-application firewall и защита сайтов |
| Databases | `/api/databases` | Подключения и запросы MySQL / MariaDB / Redis / PostgreSQL / MongoDB |
| Docker | `/api/docker` | Контейнеры, образы, тома и редактирование контейнеров |
| Files | `/api/files` | Просмотр файлов, передача, права, архивация и распаковка |
| Recycle | `/api/recycle` | Корзина (восстановление, автоочистка) |
| Terminal | `/api/terminal` | Сессии терминала по WebSocket (аутентификация через `?token=`) |
| App Store | `/api/appstore` | Установка и управление рецептами магазина приложений |
| Cron / Firewall / SSL | `/api/cron`, `/api/firewall`, `/api/ssl` | Планировщик / брандмауэр / сертификаты |
| Plugins | `/api/plugins`, `/api/op` | Управление плагинами и открытый интерфейс плагинов (GPOP) |

Полный список маршрутов и уровни доступа (`PROTECTED` / `ADMIN` / самопроверка внутри эндпоинта) — в [AGENTS.md](../AGENTS.md), раздел 3. Документация API по умолчанию отключена; для отладки задайте переменную окружения `GRAW_ENABLE_DOCS=1` и откройте `/docs`.

## Учётная запись по умолчанию

При первом запуске автоматически создаётся `backend/data/users.json`:

- Логин: `admin`
- Пароль: `admin123`
- Статус: принудительная смена пароля после первого входа

Ключ подписи хранится в `backend/data/secret.key` (создаётся автоматически при первом запуске). В продакшне берегите этот файл и `users.json`, а также смените пароль по умолчанию.

## Сброс пароля

Если вы забыли пароль администратора или не можете войти в веб-панель, сбросить пароль можно прямо на сервере с помощью консольного скрипта (запускать сервис бэкенда не нужно):

```bash
cd backend

# вывести список всех учётных записей
python reset_password.py --list

# сбросить указанную учётную запись (новый пароль вводится интерактивно)
python reset_password.py admin

# без указания учётной записи скрипт предложит выбрать её
python reset_password.py
```

Скрипт напрямую читает и записывает `backend/data/users.json`, ввод пароля скрыт, а после сброса автоматически снимается флаг «сменить пароль при первом входе». Новый пароль — не короче 6 символов.

## Конфигурация

Прокси dev-сервера фронтенда настраивается в `frontend/vite.config.js`; по умолчанию `/api` и WebSocket перенаправляются на `http://localhost:8000`:

```js
server: {
  proxy: {
    '/api': {
      target: 'http://localhost:8000',
      changeOrigin: true,
      ws: true
    }
  }
}
```

Часто используемые переменные окружения:

| Переменная | Описание |
|------|------|
| `HOST_ROOT` | точка монтирования корня хоста внутри контейнера (например, `/host`); включает режим хоста |
| `GRAW_HOST_DATA` | реальный путь каталога `data` панели на хосте; нужен для установки из магазина приложений |
| `GRAW_ENABLE_DOCS` | при значении `1` открывает `/docs`, `/redoc`, `/openapi.json` |
| `GRAW_SESSION_ONLINE_SECONDS` | порог неактивности (в секундах) для определения онлайн-сессии, по умолчанию 2 часа |
| `TZ` | часовой пояс контейнера, например `Asia/Shanghai` |
