# 05 数据存储与后台任务

> 大白话主线：Graw 「不装数据库」，它把配置、密码、凭据全用 **JSON 文件** 存在 `backend/data/` 文件夹里。后台还跑着几个常驻小任务，负责持续盯系统状态、发告警。

## 一、数据存在哪、怎么保护

所有东西都在 `backend/data/`，用文件组织。别小看这些文件，里面装的是**存取服务器的大权**（SSH 密码、数据库密码、JWT 密钥），所以要格外小心：

| 文件 | 存了什么 |
|------|---------|
| `users.json` | 用户列表、bcrypt 密码哈希、角色、token 版本号、是否开两步验证 |
| `secret.key` | 给 JWT 签名的密钥（第一启动自动生成） |
| `sessions.json` | 在线会话：会话ID、用户、IP、设备、创建时间、最近活跃时间 |
| `nodes.json` | 节点清单（含 SSH 凭据）、当前管理哪个节点 |
| `ssh_known_hosts.json` / `sshkeys.json` | SSH 主机指纹记录 / 面板生成或导入的部署密钥 |
| `agent.json` | 子节点收取模式开关与配置 |
| `plugins.json` + `plugins/<插件ID>/config.json` | 插件注册表（只存令牌哈希）与总开关 / 各插件的持久化配置 |
| `recycle.json` | 回收站开关、自动清理天数 |
| `login_logs.json` / `login_known.json` | 登录历史 / 常见登录 IP 基线（用于异地登录提醒） |
| `databases.json` / `ftp_users.json` / `netstorage.json` / `frp.json` | 各类连接凭据（数据库、FTP、网络储存、内网穿透） |
| `sites.json` / `sites_names.json` / `sitesopts_external.json` / `waf.json` / `webserver.json` | 网站清单、外部站点名、站点增强、WAF 配置、Web 引擎模式（Nginx/OpenResty） |
| `protection.json` / `firewall.json` / `cron.json` / `backup.json` / `svcmonitor.json` / `certcheck.json` / `uptime.json` | 防护、防火墙、计划任务、备份、服务监控、证书与可用性监控配置 |
| `appstore.json` / `tasks.json` / `runtime.json` | 应用商店设置、任务中心长线任务、运行时容器记录 |
| `reports/`、`config_snapshots/` | 每日巡检报告（按文件名轮转留 30 份）、写 nginx/防火墙前的配置快照 |

两道防线：

1. **启动时收紧权限**（`_secure_data_dir`）：Linux 上把 `data/` 目录设成 0700、里面文件设 0600——只有面板自己能读写，邻居用户偷不走。Windows 上 chmod 没意义，静默跳过。
2. **原子写**：写配置不是直接改原文件，而是先写一个 `.tmp`，再用 `os.replace` 覆盖。这样即使中途断电/崩溃，也不会有「写了一半的坏文件」，最多是旧文件完好无损。

## 二、后台常驻任务都在干嘛

这 7 个协程在启动时一起开、关停时一起停（配对启停，防止泄漏）；另有每日巡检报告协程与「恢复 SSH 端口转发隧道」两件启动动作：

```mermaid
flowchart TD
    A[启动时一起开的7个常驻任务] --> B[系统指标采集]
    A --> C[防篡改监控]
    A --> D[通知中心资源阈值告警]
    A --> E[站点可用性探测]
    A --> F[SSL证书到期检查]
    A --> G[服务/端口监控]
    A --> H[回收站过期条目自动清理]
    A --> I[每日巡检报告<br/>每天08:00生成并推送]
    A --> J[恢复已启用的SSH端口转发隧道]
```

| 任务 | 大白话它在干嘛 |
|------|---------------|
| **系统指标采集** | 定时取 CPU/内存/磁盘/网络/温度，喂给首页三张仪表盘（通过一条公共 WebSocket 流共享，省资源）；温度无传感器的主机自动隐藏，不造假数据 |
| **防篡改监控** | 盯着网站文件，一旦被非法改动就自动备份回滚并在线告警 |
| **通知中心** | 盯着 CPU/内存/磁盘/CPU温度 有没有超过你设的阈值，超了就按渠道（Webhook/Telegram/钉钉/企业微信/Server酱/邮件）推送；温度规则只在主机有 CPU 传感器时生效 |
| **站点可用性** | 定期探你监控的网站/服务通不通，宕机或恢复都通知你 |
| **证书到期** | 每天检查 SSL 证书还剩多少天，快过期/已过期就提醒你续 |
| **服务/端口监控** | 检查你自定义的监控项——某端口、某进程、或某个 systemd 服务是死是活，做个状态看板 |
| **回收站过期清理** | 每小时遍历本地+所有 SSH 节点的回收站，把超过保留天数（默认 30 天）的条目物理删除；开关与天数在「设置→回收站」维护 |
| **每日巡检报告** | 每天 08:00 汇总「资源 24h 概览 / 证书临期 / 服务监控异常 / 站点可用性异常 / 告警统计」五段，写成报告留 30 份并推到通知渠道；任一段失败只降级该段，不影响整份报告 |
| **SSH 端口转发恢复** | 面板重启后，把上次标记为启用的转发条目重新拉起来（本地监听强制 127.0.0.1，绝不暴露公网） |

> 约定：以后要加新的常驻监控，必须在 `lifespan()` 的启动区和停止区**同时**登记，否则协程永远挂着不回收。报告与隧道的收尾分别在 `reporting.stop_daily()` 和 `portforward.stop_all()` 里完成。

## 三、生产静态文件托管

- 前端 `npm run build` 后输出 `frontend/dist`，后端会自动检测并挂载。
  - `/assets` 下的静态资源直接给；
  - 其它非 `/api/*` 的路径做 **SPA 回退**：都返回 `index.html`，让前端根据地址栏自己决定显示登录页还是安全入口门禁。
- 安全细节：回退前会检查路径经过 `commonpath` 确保没穿越出 `dist` 目录（防目录穿越）；如果是其他盘符的绝对路径会抛 `ValueError`，代码里捕获掉，别让一个非法路径把请求搞成 500。
- `/api/*` 但没命中的路由直接返回 404，绝不误回退到前端页面。

> 一句话：数据全是 JSON 文件、权限收紧、写入原子化；后台几个常驻协程负责持续盯梢和告警。

## 四、硬件温度采集与温度告警（2026-10-02 新增）

背景：以前面板只知道 CPU/内存/磁盘「快不快」，不知道「烫不烫」——CPU 温度墙、硬盘高温都是硬件故障的前兆。现在面板直接读内核的温度传感器，把温度塞进系统概览、历史曲线，还能设阈值告警。

### 温度从哪来（只读 sysfs，零依赖）

- 首选 `/sys/class/hwmon/hwmon*/temp*_input`（coretemp / k10temp / nvme 等驱动，带 label 更可读）；
- hwmon 一个都没有时，回退 `/sys/class/thermal/thermal_zone*`（精简系统 / ARM 常见）；
- **两源不合并**：hwmon 有数据就不看 thermal，避免同一个温度出现两条重复记录；
- 容器部署时经 `host_path()` 映射到 `/host/sys/...`（与读宿主机文件同一套机制）；Windows / 虚拟机没有传感器时返回空列表，前端整块自动隐藏，绝不造假数据。

换算与判定（`app/temps.py`）：

- sysfs 里是「毫摄氏度」（45000），除以 1000 变 45.0°C；超出 -50~200°C 的读数按异常丢弃；
- 只有 CPU 类传感器算「CPU 温度」：驱动名（coretemp/k10temp/zenpower…）或 label / 热区名含 package、pkg、tctl、tdie、cpu；
- 主板（acpitz）温度不冒充 CPU 温度——宁可没有，也不误报；
- 多块硬盘 label 都叫 "Composite" 时自动消歧（加驱动名前缀，仍重名再追加序号），最多 8 条。

### 数据怎么流动

1. 系统指标采集协程每 2 秒采一帧，概览里直接带上 `temps` 字段（CPU 优先排序）；
2. 这一帧经同一条 `/api/system/ws` 广播给所有客户端——首页「系统概览」卡片在环形图下面多了一行温度（≥80°C 标红，最多显示 3 条，其余折叠成 +N）；
3. 同一帧交给 `metrics_store` 落盘：**只有存在 CPU 温度时才写 `temp` 字段**；历史曲线里缺失字段的点自然断点，不会把「没有传感器的主机」画成 0°C 一条线（聚合平均也跳过缺失行）；
4. 通知中心的后台检查循环里多看一个指标 `temp`：**没有 CPU 传感器就跳过**（取 None，不触发），有就按你设的阈值告警（单位 °C，文案按 °C 而不是 % 显示）。

### 远端节点怎么算

- 配了 Agent 的子节点：整条 `/api/system/*` 被中间件代理到子节点自己的面板，温度由子节点采自己主机的，天然正确；
- 只有 SSH 的远端节点：主面板的批量采集脚本 `_REMOTE_SCRIPT` 里加了 `HWMON` / `THERMAL` 两段（cat 远端 sysfs），解析规则与本地完全一致（`_remote_temps()` 复用同一套换算 / 判定 / 排序）。

```mermaid
flowchart TD
    A[每 2 秒采集协程] --> B{当前节点是远端吗}
    B -- 本地 --> C[读 hwmon，空则回退 thermal<br/>host_path 映射 /host]
    B -- SSH远端 --> D[批量脚本取回 HWMON/THERMAL 分段]
    B -- Agent子节点 --> E[请求被代理到子节点面板<br/>由子节点自行采集]
    C --> F[换算+过滤+CPU判定+排序消歧]
    D --> F
    F --> G[概览字段 temps]
    G --> H[WS 广播 → 首页卡片温度行]
    G --> I[metrics_store 落盘 temp<br/>仅 CPU 温度存在时]
    I --> J[历史监控窗口温度曲线<br/>有数据才出现]
    G --> K[通知中心阈值检查<br/>无传感器自动跳过]
    K --> L[超阈值 → 渠道推送 单位°C]
```

关键文件与函数：`app/temps.py`（`collect_temps` / `cpu_temp` / `is_cpu_sensor` / `normalize_sensors`）；`routers/system.py`（`_overview_sync` 附 temps、`_remote_temps`、`_REMOTE_SCRIPT`）；`metrics_store.py`（`record_sample` / `history` 的 temp 可缺省字段）；`routers/notify.py`（`METRICS` 增加 temp、`_read_metrics`、`_alert_message` 单位）；前端 `RingCard.vue`（温度行）、`MetricsHistoryWindow.vue`（温度图）、`NotifyRuleFormWindow.vue` / `NotifyWindow.vue`（CPU 温度规则项）。

> 一句话：温度走「sysfs → 概览帧 → WS/落盘/告警」三条下游；哪里有传感器就在哪里出现，没有就整体安静隐藏。
